## 🚀 Настройка сервера и конфигурация автозапуска (Systemd)
Для того чтобы бот работал непрерывно и автоматически запускался при перезагрузке сервера, настроена служба автозапуска через системный менеджер `systemd`.

### 1. Создание файла конфигурации службы
В директории `/etc/systemd/system/` создан файл `tgbot.service` со следующим содержимым:
```ini
[Unit]
Description=Telegram Habit Tracker Bot
After=network.target

[Service]
User=root
WorkingDirectory=/root/telegram-bot
ExecStart=/usr/bin/python3 bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

### 2. Команды управления службой (Запуск, Остановка, Логи)
* **Запуск бота:** `sudo systemctl start tgbot`
* **Остановка бота:** `sudo systemctl stop tgbot`
* **Включение автозапуска при перезагрузке:** `sudo systemctl enable tgbot`
* **Проверка статуса службы:** `sudo systemctl status tgbot`
* **Просмотр логов в реальном времени:** `journalctl -u tgbot.service -f`

## 🔍 Проверка надежности системы при перезапуске
В ходе тестирования седьмого этапа была проведена полная проверка поведения системы при аварийном выключении или перезапуске сервера/компьютера:
1. **Сохранение очереди:** Все неотправленные из-за сбоя сети напоминания успешно фиксируются в постоянной таблице `pending_reminders` базы данных SQLite.
2. **Автоматическое восстановление:** При повторном запуске скрипта (`python bot.py`) функция `restore_queue_on_start()` автоматически считывает все записи со статусом `pending` из БД и поднимает их в фоновых потоках `threading.Thread`.
3. **Результат:** Напоминания гарантированно доставляются пользователям после восстановления работоспособности системы, дублирования или потери уведомлений не происходит.

## 👥 Отчет о тестировании (Список замечаний 5 пользователей)
Бот был передан фокус-группе из 5 человек для проверки живыми людьми. По результатам тестирования были зафиксированы следующие замечания и внесены исправления:

1. **Пользователь 1 (Али):** Заметил, что при вводе пустой строки в названии привычки бот падал.
* *Исправление:* Добавлена жесткая валидация `if not text` на шаге `WAITING_NAME`.
2. **Пользователь 2 (Лейла):** Попросила сделать формат времени более строгим, так как при вводе некорректных букв вместо времени бот ломался.
* *Исправление:* Внедрена проверка формата через регулярное выражение `re.match` для формата ЧЧ:ММ.
3. **Пользователь 3 (Дмитрий):** Обнаружил, что инлайн-кнопки отметки привычек выдавали ошибку при нажатии из-за неверного парсинга ID.
* *Исправление:* Код обработчика `handle_habit_click` исправлен на `int(call.data.split('_')[1])` для точного извлечения числового ID.
4. **Пользователь 4 (Айсель):** Заметила, что если заблокировать бота, он бесконечно пытался отправить напоминание и забивал логи ошибкой 403.
* *Исправление:* Добавлен перехват ошибки 403 с автоматической деактивацией привычек пользователя.
5. **Пользователь 5 (Эльдар):** Предложил добавить команду отмены диалога, если передумал создавать привычку посреди процесса.
* *Исправление:* Создана и полностью протестирована команда `/cancel`.
